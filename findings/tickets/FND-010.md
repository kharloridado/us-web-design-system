**Finding `FND-010`** · type `a11y/contrast` · severity `high` · `[node:1868-83]`

The USWDS `accent-warm` button paints white label text on its orange fill in its **resting**
state. That measures **2.24:1**.

### What the design states

| | Value | Figma variable |
|---|---|---|
| Fill | `#FA9441` | `Accent warm/accent-warm` |
| Label | `#FFFFFF` | `Base/white` |
| Label type | 16px **Bold**, Public Sans | — |

Both colours are bound Figma variables on node `1868-83`, symbol `1868:138`
(`Type=accent-warm, State=default`). This is not an inference from a layer name.

### The rule it conflicts with

**WCAG 2.2 SC 1.4.3 Contrast (Minimum)** — 4.5:1 for normal text, 3:1 for large.

16px Bold is **normal** text: the large-text threshold begins at 18.66px bold (14pt). So the
4.5:1 bar applies — and 2.24:1 does not clear even the 3:1 large-text bar, so the outcome is
the same under either reading.

### How it was measured

- Computed from the ref's own hexes (sRGB relative luminance, WCAG 2.2 formula).
- Independently measured in headless Chrome on the real `.btn` element under the full
  cascade — OutSystems UI base + theme + block override — at 1280x900 and 375x812.
- Both agree at 2.24:1.

**Refutation attempted and failed.** A colour that fails contrast is only a finding if
something actually renders it as text. This one does: `.uswds-btn--accent-warm` renders its
label in the build's own specimen, and it is a documented variant a developer is expected to
reach for. Real rendered usage; not a theoretical token.

### Recommendation

**A — ink foreground (recommended).** `--color-base-ink` `#1B1B1B` on `#FA9441` = **7.69:1**.

This is the pattern **the design already uses on its other two bright fills**:

| Variant | Fill | Resting label | Measured |
|---|---|---|---|
| `accent-cool` | `#00BDE3` | `#1B1B1B` ink | 7.70:1 |
| `success` | `#00A91C` | `#1B1B1B` ink | 5.49:1 |
| `accent-warm` | `#FA9441` | `#FFFFFF` white | **2.24:1** |

`accent-warm` is the one bright fill that does not take ink, which is what makes this look
like drift rather than an intentional exception. Both of the others also flip to white on
hover and active, so the pattern is available without inventing anything.

**B — keep white, re-point the resting fill** to `accent-warm-dark` `#C05600` = **4.59:1**.
Passes, but collapses the default and hover steps onto the same colour.

All values recomputed before filing.
